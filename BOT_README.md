# Spirit Breaker support: автономный прототип

## Версия 0.1.7: закуп и группировка

- Стартовый набор строго: Wind Lace, две Iron Branch, Tango и Faerie Fire.
- Затем основная очередь: Boots of Speed → Phase Boots → Shadow Blade →
  Yasha and Kaya (по умолчанию) либо Eul при наблюдаемой потребности в
  диспеле/контроле → Silver Edge. Ситуативные защитные и поздние предметы
  рассматриваются только после этого ядра.
- Tango используется на наблюдаемом дереве при нехватке здоровья и отсутствии
  противника вплотную; повторное лечение не накладывается поверх активного Tango.
- В режиме group с 10:00 до 30:00 pos 1 получает последний приоритет: бот
  предпочитает другого саппорта, затем pos 2/3. После 30:00 выбирается ближайшая
  подходящая группа без штрафа роли.
- 90 контрактных и сценарных тестов.

## Версия 0.1.6: Charge как глобальный транспорт

- Видимый противник с 25% HP или меньше становится приоритетной целью Charge,
  если хватает маны, способность готова и точка не выглядит самоубийственной.
- После восстановления на базе бот при недоступном TP выбирает поддержанную
  драку либо безопасного вражеского крипа как цель Charge.
- После линии разрешён Charge в свободного lane/neutral creep, когда нет драки,
  угрозы и союзного кора рядом с фармом.
- По записи человека прокачка начинается Greater Bash → Charge → Bulldoze;
  Bulldoze разрешён во время Charge ближе к столкновению.
- Набор контрактных и сценарных проверок: 85 тестов.

## Исправление 0.1.3: участие в локальной драке

Charge с `AbilityCastRange=0` в поставляемом KV больше не отбрасывается как
каст без дальности: это исключение только для глобального Charge. Ближайшая
союзная драка распознаётся независимо от режима патруля/вардинга, включая
первый уровень. Межлинейные ганги по-прежнему начинаются со второго.
Обычная атака союзника по крипам сама по себе не считается командной дракой.
Во время продолжающейся драки нет обязательного отхода после каждого удара;
сохраняются проверки здоровья, сил и вражеских башен. Подход к цели расширен
до 1100 единиц. 71 тест проходит, включая реальную нулевую дальность Charge.

## Исправление 0.1.2: активный саппорт

- Новый `src/support.lua`: устойчивые точки перемещения у края пачки,
  короткие подходы для размена, отход после удара и защита раненого кора.
  Движение к более безопасной позиции не требует численного перевеса.
- Ганги других линий со 2-го уровня: нужен готовый Charge, запас HP/маны,
  видимый противник и союзник, который может помочь. Кора под давлением бот
  не оставляет. Проверяются известные башни вдоль прямого пути Charge;
  между попытками ротации — минимум 25 секунд. Ганк не обязателен на каждом кулдауне.
- Вардинг отдельным observer в безопасной точке даже при наличии противников
  на другой стороне линии. Добавлены точки боковых линий. Ограничение на
  непроверенный режим объединённого dispenser сохраняется.
- Уровень читается через документированный `NPC.GetCurrentLevel`, а не
  отсутствующий `NPC.GetLevel`. Уровень виден под кнопкой.
- Убраны массовые запросы несуществующих special values у всех предметов и
  талантов; читаются только реально используемые значения нужной способности.
- 67 тестов, включая 12 новых регрессий; игровая эффективность ещё требует лобби.

Сборка: `dist/spirit_breaker_bot.lua`. Установка: `C:\Umbrella\scripts\spirit_breaker_bot.lua`.
Только Spirit Breaker в локальном/приватном лобби. Это интегрированная версия для
игровой проверки, **не подтверждённый полным матчем готовый бот**.

## Запуск

1. Включить `spirit_breaker_bot.lua` в списке скриптов Umbrella. Старый
   `mid_t1_start` не должен оставаться загруженным одновременно.
2. Выбрать Spirit Breaker в приватном лобби. Кнопка `Bot: ON` появляется слева
   сверху. Короткий клик переключает контроллер; перетаскивание не переключает.
3. Включить свои встроенные autobuy/autocourier. Контроллер заполняет quick-buy,
   но сам не выполняет покупку или доставку. Bridge и Python не нужны.
4. Ошибки и решения: `C:\Umbrella\debug.log`, префикс `[SpiritBreaker`.
   Успешная загрузка содержит `Loaded autonomous controller; recorder OFF, external OFF`.

По умолчанию Bot включён. Ручной приказ не ставит бота на паузу: контроллер
возвращает свой приказ с ограниченной частотой. Для ручной игры нажать OFF.
Внешний bridge, нейросеть, запись приказов и датасета по умолчанию выключены.
Новый скрипт не имеет функции записи. Старые `data/` и `dataset/` сохранены.

## Реализованные правила

- Арбитр desire с удержанием режима и hysteresis. Быстрые проверки безопасности
  каждый OnUpdate, полная оценка примерно 8 раз/с. Один исполнитель приказов.
- Выбор pos4/offlane и pos5/safe lane; неопределённая роль → pos5.
  Интерпретация флагов 8/16 сохранена по плану. Документация описывает поле,
  но не значения битов: реальная проверка обеих ролей ещё нужна. Raw flags есть
  в наблюдении и логе.
- Позиция около кора, умеренный харас, денай, защита кора, отход от башенного
  фокуса и раннего агро крипов. До 10:00 вражеский ластхит допускается только
  когда союзный кор расчётно не успевает; обычный фарм не имеет приоритета.
- Charge для близкого прерывания, поддержанной драки или осторожного добора;
  Bulldoze, Nether Strike, опциональный Planar Pocket. Прокачка доступных
  способностей и талантов по реальным именам и CanBeUpgraded.
- Wand/stick, Force, Glimmer, Lotus, BKB, phase, urn/vessel, salve/clarity,
  smoke/dust и безопасный TP. Требуются актуальная возможность применения,
  корректный тип цели и наблюдаемые условия. Force проверяет направление взгляда.
- Наблюдаемые руны, одиночные observer/sentry, атака обнаруженного варда,
  pull/stack по коробкам лагерей и наблюдаемому движению нейтралов.
- Группировка, защита и пуш башен под прикрытием крипов, помощь уже бьющей
  Roshan/Tormentor команде, свободный фарм после линии и восстановление на базе.
- Ситуативная очередь support-предметов; наблюдение владения включает stash
  и своего курьера. Пополнение observer не стирает незавершённый крупный предмет.
- GridNav.BuildPath + оценка сегментов и альтернатив через промежуточные точки.
  Это не модифицированный A*: Umbrella не принимает наш callback стоимости.
  Если безопасного маршрута нет, приказ движения не отправляется.

Это ограниченный перенос применимых правил, а не весь OpenHyperAI с заменой
имён функций. FretBots, чаты, бонусы сложности и другие герои не запускаются.

## Явные ограничения

- **Ward dispenser отключён:** тип выбранного варда не подтверждён API.
  Отдельные observer/sentry поддержаны. Если игра объединила их, будет сообщение
  в логе, а не попытка поставить случайный тип.
- **Захват outpost отключён:** безопасный приказ захвата не подтверждён.
  API возвращает `outpost_capture_unverified`.
- Нет точного документированного NPC.GetAttackTarget для обычных NPC.
  Башни используют Tower.GetAttackTarget; дальние атаки — OnProjectile с
  `isAttack`; ближняя драка и агро лагерей используют помеченные эвристики
  по дистанции, движению, атаке и потере здоровья. Это не точное знание агро.
- Снаряды линейных заклинаний наблюдаются, но универсальное гарантированное
  уклонение по неизвестной ширине/эффекту не заявляется.
- Неизвестное место не считается пустым. Через туман не читаются текущие
  позиции/HP/модификаторы врагов. Карта, вардинг-точки и pull/stack требуют
  проверки на текущей карте; тайминг стака оценивается, успех не гарантирован.
- Без подключённых autobuy/autocourier бот не получит заказанные предметы.

## Модули и сборка

`src/`: core, adapter, map, threat, navigation, modes, hero, items, executor,
arbiter, api, json, bridge, ui, main. Общий контракт — `src/CONTRACT.md`.
`build_bot.py` встраивает модули и MIT-лицензию в один Lua-файл; require в игре
не используется. `dist/manifest.json` сопоставляет модули со строками сборки.

Для разработки нужны Python, Node, `pip install -r requirements-dev.txt`
и `npm install --ignore-scripts`. Это инструменты сборки/тестов, не игры.

```
python -m unittest test_bot test_bridge -v
python build_bot.py --deploy
```

Или `build_and_deploy.bat`. Перед установкой старые активные версии копируются
в уникальный `archive/pre-rulebased-*`, старый файл удаляется **только из папки
активных скриптов**. Для отката выключить новый скрипт и вернуть старый из архива.

## Проверка, выполненная в разработке

67 тестов проходят: 59 сценариев нового Lua-контроллера/интерфейса и 8 прежних
тестов Python bridge. Lua исполняется в Lupa Lua 5.4 с mock API; собранный файл
проверяется luaparse. Есть прогон виртуальных часов на 30 минут — **это не
реальный матч**, в нём нет движка Dota, физики, pathfinding или боевого баланса.

В первом реальном запуске найдено отсутствие `_G` в sandbox Umbrella. Доступ
заменён явным реестром API; все тесты теперь запускаются без `_G`, `os`, `io`,
`debug`. Исправление установлено; повторная загрузка пользователем ещё нужна.

Не подтверждены: загрузка исправленной версии loader, живые роли Radiant/Dire pos4/5,
точность агро/стака/вардинга и полный матч не менее 30 минут. До этого нельзя
утверждать отсутствие runtime-ошибок в настоящей Umbrella.
